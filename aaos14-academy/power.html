Power Management & Garage Mode

A phone has a battery and a user who presses the power button. A car has a 12V battery that must survive weeks in a parking lot, and Android must be “instantly on” when the driver opens the door. That is why AAOS has its own power state machine.

⏱ 20 min read🎯 Intermediate📂 service/src/com/android/car/power

3.1.1Overview

The authority over power does not live in Android but in the MCU (which knows the key state, doors and battery voltage). Android only “negotiates” with the MCU through two Vehicle Properties:

AP_POWER_STATE_REQ VHAL → Android

The MCU commands: ON, SHUTDOWN_PREPARE (with a parameter such as CAN_SLEEP, CAN_HIBERNATE, SHUTDOWN_ONLY, SLEEP_IMMEDIATELY…), CANCEL_SHUTDOWN, FINISHED.

AP_POWER_STATE_REPORT Android → VHAL

Android reports: WAIT_FOR_VHAL, ON, SHUTDOWN_PREPARE, SHUTDOWN_POSTPONE, DEEP_SLEEP_ENTRY/EXIT, HIBERNATION_ENTRY/EXIT, SHUTDOWN_START, SHUTDOWN_CANCELLED.

On the Android side, CarPowerManagementService (CPMS) inside CarService owns the state machine; apps and system services listen via CarPowerManager.setListener() / addPowerPolicyListener(). “AP” (Application Processor) is the SoC running Android.

🎭
Analogy

The MCU is the building manager holding the master key; Android is an office worker. When the manager announces “the building is closing” (SHUTDOWN_PREPARE), the worker saves their files, may ask for extra time to finish pending tasks (SHUTDOWN_POSTPONE — Garage Mode), then reports “I'm leaving” (DEEP_SLEEP_ENTRY). Only the manager may flip the main breaker.

⚠️
Common pitfall

Apps that listen for SHUTDOWN_PREPARE to save data must be fast and must not assume a real shutdown follows: if the driver reopens the door, the system jumps back to ON without rebooting. After Suspend-to-RAM, network connections, sockets and timers may be stale — handle SUSPEND_EXIT.

3.1.4Garage Mode — sequence flow

Garage Mode is the window after the ignition is turned off during which Android keeps running (screen dark, no audio) to do background work: downloading OTA updates, dex optimization, data sync. Apps schedule work with JobScheduler using setRequiresDeviceIdle(true) — in a car, “idle” means Garage Mode.

🎭
Analogy

Garage Mode is the night cleaning crew at a shopping mall: the customers have left (driver gone), the lobby lights are off, but staff still mop the floors and restock shelves (OTA, sync). They must finish before the doors are locked (timeout), and if a customer comes back (CANCEL_SHUTDOWN) they stop immediately and reopen.

3.1.5Power Policy & Remote Access

A power policy defines which components are enabled in each state (AUDIO, DISPLAY, WIFI, BLUETOOTH, CELLULAR, LOCATION, MICROPHONE…). CPMS works with the carpowerpolicyd daemon to apply them. OEMs define policies in /vendor/etc/automotive/power_policy.xml.

System policyUsed whenMain effect
system_power_policy_all_onONAll components enabled.
system_power_policy_initial_onEarly bootOnly the minimum (audio, display, CPU) for a fast first frame.
system_power_policy_no_user_interactionGarage ModeDisplay, audio, microphone and input off; network and CPU kept on.
system_power_policy_suspend_prepBefore suspendGradually disables components to sleep safely.
🆕
Android 14: Remote Access

Android 14 adds CarRemoteAccessManager and the IRemoteAccess HAL: a remote server (via the TCU) can wake Android while the car is asleep to run a task (e.g. a nightly OTA download), then go back to sleep. It complements Garage Mode — Garage Mode runs right after ignition off, Remote Access runs whenever the car is woken.
